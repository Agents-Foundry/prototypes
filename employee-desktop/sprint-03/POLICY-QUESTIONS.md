| EMP-DEC-01 | Window architecture | **APPROVED — Option B:** Secure cross-platform native desktop shell for Windows, macOS and Linux; present a native-feeling agent window while isolating untrusted UI rendering from the separate agent execution kernel, tool execution, filesystem operations and privileged OS integrations. Enforce tenant-scoped identity and least-privilege tool capabilities with explicit authorization for sensitive actions. Secrets must remain behind OS keychain / approved broker boundaries and never flow into ordinary UI state, logs or conversations. Apply safe IPC contracts, narrow process permissions, failure isolation, audit and revocation. Design screens, permissions, states and interaction flows before any application implementation. | Product owner approved 2026-10-16; independent reviews pending |
| EMP-DEC-02 | Conversation and context persistence | **APPROVED — Option B:** Organization-scoped central authoritative synchronization of versioned conversations, agent runs, approvals, artifacts and accessible history, with employee/workspace/agent-level tenant isolation. Permit only encrypted, OS-key-protected, policy-bounded local caches for performance/offline recovery; do not cache secrets. Keep short-lived conversation context distinct from durable organization knowledge, with provenance, scope, expiry and controlled deletion. Surface syncing, conflicts, stale context, offline and failed-upload states; resolve conflicts safely rather than silently overwriting. Follow retention, residency, privacy and legal-hold obligations. Membership/device revocation blocks access and invalidates cached data as soon as technically enforceable. Audit context access, sharing and deletion without exposing private content to platform telemetry. | Product owner approved 2026-10-16; independent security review pending |
| EMP-DEC-03 | Credential and token handling | **APPROVED — Option B:** Store device-bound user credentials with appropriate OS-native keychain/secret facilities, and managed organization credentials in approved enterprise vaults. A least-privilege credential broker mediates tenant/user/agent/tool/environment/operation/time-scoped capability access and favors brokered operations or short-lived tokens over unrestricted secret disclosure. Prefer approved OAuth authorization-code + PKCE/enterprise SSO flows. Enforce rotation, expiry, renewal, revocation, device loss and offboarding. Production credentials and privileged or destructive operations require explicit policy checks, step-up and human approval where indicated. Never persist or expose secrets in conversations, memory, ordinary UI settings, model prompts, telemetry, logs or artifacts; redact tool outputs/errors and audit scoped requests without credential values. | Product owner approved 2026-10-16; independent security review pending |
| EMP-DEC-04 | Environment and production permissions | **APPROVED — Option B:** Every run and tool action explicitly identifies tenant, employee, target environment and authorized scope. Isolate development, playground, staging and production credentials, accounts, tools, data and execution permissions. Apply least privilege and default production observation/sanity checks to read-only. Privileged production writes require fresh step-up and risk-appropriate human authorization, including independent approval where policy requires. Deny uncontrolled deletion, bulk mutation and irreversible testing. Prevent production data/credential transfer to lower-trust environments or model prompts/logs. Handle pause, timeout, credential expiry, interruption and rollback with auditable states. Fail closed on ambiguous target, missing permission or stale approval; retain sanitized execution evidence. | Product owner approved 2026-10-16; independent security review pending |
| EMP-DEC-05 | Agent run autonomy | **APPROVED — Option B:** Risk-based autonomy allows only preauthorized, policy-scoped low-risk reads and local analysis. Sensitive external writes (Jira publication, repository changes, disruptive tests), privileged production operations, deployments, irreversible or destructive actions require scoped human approval, step-up and independent authorization where policy requires. Bind each approval to exact tenant, employee, agent, operation, target environment, parameters, data impact, authorizer and expiry; a changed execution plan or context requires fresh evaluation. Pause and resume only after validated authorization, prevent agent self-approval, and allow safe cancellation, stop and revocation with in-flight action handling. Denied, expired, missing or ambiguous authorization fails closed without broad-permission retry. Keep immutable decision/action evidence with credential and sensitive-content redaction. | Product owner approved 2026-10-16; independent security review pending |
| EMP-DEC-06 | Workspace repository access | **APPROVED — Option B:** Only organization-approved tenant/project/repository/branch scopes may be accessed, with read-only inspection as the default. Each task/agent uses an isolated, restricted execution workspace with safe cleanup and cross-tenant separation. Git credentials remain in the approved broker, never model context or untrusted workspace. Require risk-scoped human authorization for commits, pushes, pull requests, branch deletion and protected branch operations; display diffs, conflicts and stale upstream context before writes. Shell, network, filesystem traversal and dependency execution are policy limited; treat repository content and instructions as untrusted to block prompt-injection privilege escalation. Audit access, approvals, sanitized operation results and recovery paths without unauthorized code disclosure. | Product owner approved 2026-10-16; independent security review pending |
| EMP-DEC-07 | Browser automation and test evidence | **APPROVED — Option B:** Browser testing uses dedicated tenant/employee/run/environment-isolated profiles; personal cookies and unrelated sessions are never silently reused. Enforce approved origins, redirects, downloads and network destinations plus brokered, scoped, short-lived authentication. Permit policy-scoped nondestructive tests and require risk-appropriate human approval for sensitive mutations, payments, destructive flows or production writes. Use controlled fixtures, synthetic identities and safe cleanup; surface browser target, steps, pause/stop and permission state. Bind trustworthy screenshots, traces and test results to run ID, target environment, release/build and timestamps with provenance and redaction of secrets and sensitive page data. Fail honestly on timeout/crash/stale sessions; retry only safely. Jira defect publishing and result updates remain human reviewed and authorization gated. | Product owner approved 2026-10-16; independent security review pending |
